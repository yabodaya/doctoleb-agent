# VS-002: Messaging database
Status: TODO

## Goal
Our own tables for messaging, with Alembic migrations.

## Scope
Tables (all with tenant_id where applicable, created_at/updated_at):
- webhook_inbox (unique provider_event_id, raw payload JSON, status, attempts)
- contacts, contact_identities (channel + external id, unique per tenant)
- conversations (state: AI_ACTIVE / HUMAN_REQUESTED / HUMAN_ACTIVE / CLOSED)
- messages (direction, modality, provider_message_id unique, text, status)
- dead_letter_jobs
Repositories with tenant-scoped query helpers.

## Out of scope
Clinic/appointment tables (Booking Service owns them).

## Acceptance
- `alembic upgrade head` on empty DB works; downgrade works
- Tests: inserting a duplicate provider_event_id fails; repository queries require tenant_id

## Understand first
Primary/foreign keys, unique constraints (they are what make deduplication safe).
