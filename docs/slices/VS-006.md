# VS-006: Agent Core + first tool
Status: PARTIAL

## Goal
"Is Dr. Karim available tomorrow afternoon?" -> AI calls search_available_slots -> real answer.

## Scope
- BookingClient protocol + FakeBookingClient (seeded doctors, services, slots)
- Tool framework: tool registry, Pydantic arg validation, tool execution logging (agent_runs, tool_executions tables)
- Tools: get_clinic_information, list_doctors, search_available_slots
- Tool-calling loop with a max-iterations limit
- Date handling: "tomorrow afternoon" resolved against Asia/Beirut time given in the prompt

## Acceptance
- The Dr. Karim flow works on WhatsApp with fake data
- Invalid tool args from the model are rejected and the model is told why
- Tests: tool loop terminates; tenant_id never appears in tool schemas

## Understand first
Tool/function calling: the model REQUESTS, our code EXECUTES and decides.

**The loop.** `process_turn(turn, chat, runtime)` runs at most
`MAX_MODEL_CALLS = 4` model calls under ONE `asyncio.timeout`. Four is three for
the normal flow (list, search, answer) plus one for a single self-correction
after an invalid-arguments error - a test pins that the correction path fits.
The count is a constant, not a setting: a deployment that could raise it could
raise the bill without a code change.

**The budget arithmetic** (decision D4, plan section 5.2):

```
OPENAI_TIMEOUT_SECONDS      30   ONE model call, inside the turn budget
AGENT_TURN_TIMEOUT_SECONDS  45   the WHOLE loop: <=4 calls plus every tool call
META_SEND_TIMEOUT_SECONDS   10   the one Meta send
--------------------------------------------------------------------
network worst case          55
JOB_TIMEOUT_SECONDS    60 -> 90  must exceed 55; leaves 35s for four transactions
claim lease            90 + 30 = 120 > 90, so the lease outlives the job
```

`OPENAI_TIMEOUT_SECONDS` dropped OUT of the job relation: every model call now
happens inside the turn budget, and four of them at 30s each would be 120s.

**What is recorded, and what never is.** `agent_runs` holds one row per turn
that reached T1b; `tool_executions` holds one row per tool call the model asked
for, executed or not. Both hold **codes, counts, durations and our own row
UUIDs, and nothing else**. Never stored: patient text, model text, tool
arguments, tool results, doctor names, slot times, OpenAI's tool-call ids, a
tool name the model invented (stored as `unknown`), or an argument key we did
not declare. A test pins the exact column set of both tables, so adding a
`result` column means consciously editing it.

**Tenant ids are opaque strings** (decision D1). Six columns became `TEXT`;
`TenantId` is `str`; nothing parses, normalises or case-folds one. Q2's hygiene
refuses a non-string, an empty string, leading/trailing whitespace and any
non-printable character - the last because the value becomes an `X-Tenant-Id`
header.

**The prompt is `vs006-1`**, pinned by SHA-256, with a second pin (Q13) over the
tool specs and the clock-message template: a tool description instructs the
model as much as the prompt does, and the three time periods live there.

**Clinic time** is injected as a separate `system` message each turn, never put
in the prompt (which would break the pin). `tzdata` is now a runtime dependency:
a Windows host has no system time zone database at all, so without it every
clock test failed locally while passing in the container.

**The booking data is the in-memory FAKE**, and the worker warns about it on
every start. That warning, plus obviously synthetic names and a fictional
address, is the whole mitigation until VS-011.

**SDK facts observed in Task 0** (openai 3.20.0, plan check U2): tool-call
arguments are a `str` and are passed through untouched even when they are not
JSON; `content` is `None` on a pure tool turn; a tool call whose `type` is
unknown still parses, with `function is None`; `type: "custom"` parses into a
class with no `.function` at all; a function call with no `arguments` key gives
`arguments is None`; and `finish_reason == "stop"` with tool calls present
parses fine. All of these are handled, and all are covered by tests.
